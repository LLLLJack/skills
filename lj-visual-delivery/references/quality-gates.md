# Visual Quality Gates

交付前同时验证“文件能用”和“画面成立”。没有实际打开或渲染过，就不要声称已视觉验证。

## 1. 致命项

任一项失败都必须修复：

- 文件打不开、脚本报错、图表或图片空白
- 文本溢出、遮挡、被裁切，或关键内容落在安全区外
- 对比度导致正文难读
- 用户要求的格式、尺寸、页数或必备内容缺失
- 数据、标签、单位、图例或来源明显错误
- 交互页面没有基本的键盘焦点或移动端可用性

## 2. 视觉评分

每项按 0 / 1 / 2 分评估。出现 0 分必须返修；建议总分至少 15/18。

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 任务特异性 | 换个品牌也成立 | 有部分定制 | 内容、视觉和领域紧密相连 |
| 焦点与层级 | 不知先看哪里 | 基本可读 | 一眼抓住主结论，次序明确 |
| 构图 | 拥挤或松散 | 规整但普通 | 块面、留白和节奏有意图 |
| 字体 | 难读或混乱 | 安全可用 | 字体角色明确且有性格 |
| 色彩 | 随意或低对比 | 一致 | 色彩承担层级与语义 |
| 图像与图表 | 装饰或不匹配 | 能说明内容 | 成为证据、情绪或记忆点 |
| 细节工艺 | 明显粗糙 | 基本整齐 | 对齐、裁切、线条和间距精确 |
| 系统一致性 | 每块各自为政 | 大体一致 | 变量、组件和重复母题统一 |
| 媒介适配 | 像另一种媒介硬套 | 基本合适 | 阅读距离、尺寸和交互均匹配 |

## 3. 渲染复检顺序

### 全局视图

- 缩到 20–30% 或查看整页/整套缩略图。
- 做“眯眼测试”：是否仍能看出唯一焦点、章节节奏和重点色？
- 检查是否连续出现相同构图，或每一块都争夺注意力。

### 目标尺寸

- HTML：至少检查桌面宽度和一个窄屏宽度。
- 幻灯片：在整套 montage 中看节奏，再逐页看投影可读性。
- 海报：同时看 100% 和约 10–15% 的缩略图。
- 数据图：检查标签、单位、零值、空值、极值和颜色语义。

### 局部视图

- 检查断行、字距、行高、图像裁切、边框、阴影、圆角和基线。
- 检查图标是否来自同一风格，照片是否有统一色调或处理。
- 检查按钮、图例、脚注与小字是否仍然清楚。

## 4. 返修策略

一次返修只解决评分最低的 1–3 项：

1. 先修内容和层级。
2. 再修构图和密度。
3. 再修字体、颜色和图像。
4. 最后修质感与微小间距。

不要在结构错误时继续加阴影或动效。通常做 1–2 次集中返修即可；如果仍不成立，换构图或 art direction，而不是继续抛光错误方向。

## 5. 技术检查

### HTML

在 skill 根目录下可运行：

```bash
node scripts/check_html.mjs output.html
node scripts/render_html.mjs output.html --output preview.png --width 1440 --height 1000
node scripts/render_html.mjs output.html --output preview-mobile.png --width 390 --height 844
```

等价的浏览器、Playwright、截图或预览工具也可以。检查控制台错误、网络失败、重复 ID、缺失本地资源与响应式溢出。

### 幻灯片

- 检查所有页的尺寸与安全边距。
- 导出整套缩略图或 PDF，检查节奏和字体替换。
- 对数据页和封面单独放大检查。
- 若使用 PPTX，重新打开导出的文件，确认元素没有错位。

### 海报与静态图

- 确认实际像素、色彩模式和输出格式。
- 印刷稿检查出血、安全边距和图片分辨率。
- 关键信息保持为可编辑文字或矢量；不要让生成图片承担日期、价格、网址等精确信息。
