# Visual Deliverables — 将用户的HTML、SVG、CSV、PPTX 等交付物做得「好看又专业」）。此技能可以将成果制作成好看、专业、可交付的文件。用于用户需要 HTML 报告、仪表盘、幻灯片、信息图、海报、图表、对比表、研报式分析或其他视觉化交付物，或要求结果精致、专业、不像 AI 生成、排版良好、可作为文件分享时。

## 这个技能是什么

它把「AI 生成的内容为什么能好看」拆成 **三层可复用的机制**，并附带可直接套用的规范与骨架。  
所谓「用某些指令 / 方法引导呈现」，对应的就是下面第 1、2 层的思想。

| 层 | 管什么 | 一句话 |
|---|---|---|
| ① 交付行为层 | 结果以什么形式给到用户 | 写成文件、给路径且直接发给到用户，别把代码糊在对话里 |
| ② 视觉美感层 | 配色 / 字号 / 布局 / 审美禁忌 | 禁止「AI 味」，用有品味的克制设计 |
| ③ 场景排版层 | 特定交付物（HTML 报告 / 幻灯片）的固定格式 | 研报风、幻灯片字号契约等 |

## 何时使用

- 用户要 HTML 报告、仪表盘、幻灯片、信息图、海报、任何视觉化交付物
- 用户希望输出「精致 / 专业 / 不像 AI 生成」
- 用户说结果要排版好、好看、可当作文件分享
- 要画图表、对比表、研报式分析

## 第 1 层：交付行为

原则：

1. **结果即文件**：凡是用户会「看 / 分享 / 打开」的成果（HTML、SVG、MD、CSV、PPTX 等），都写成一个**自包含文件**，在结尾把文件直接发送到用户手中。
2. **对话里少啰嗦**：不要在聊天里复述文件内容。给一句结论 + 文件路径即可。文件才是交付物，对话只是引导。
3. **自包含**：HTML 要内联 CSS/JS、用 CDN 引库（注明来源），用户双击即可在浏览器打开，无需本地服务（除非确实必要）。SVG/CSS 不依赖 JS，天然更稳。
4. **主题一致**：浅色界面用浅底深字，深色界面用深底浅字；正文与标题对比度达标、可读。
5. **可验证**：交付前自检（见第 3 层 HTML 报告的 `node --check` 规则）——**图表能渲染才算完成**。

## 第 2 层：视觉美感（核心规范）

详见 `references/visual-style-guide.md`。要点速记：

- **基线三变量**：`DESIGN_VARIANCE=8`、`MOTION_INTENSITY=6`、`VISUAL_DENSITY=4`（按需求动态调整）。
- **禁止 AI 味（AI Tells）**：
  - 不用纯黑 `#000000` → 用 Zinc-950 / 炭灰
  - 不用紫蓝 AI 渐变发光；最多 1 个低饱和强调色（饱和度 < 80%）
  - 不用 `Inter` 字体 → 用 `Geist` / `Outfit` / `Cabinet Grotesk` / `Satoshi`
  - 不用超大 H1 硬撑层级（用字重 + 颜色 + 间距控制层级）
  - 不用 3 等宽卡片排布（用 Zig-Zag / 非对称网格 / 横向滚动）
  - 不用通用占位名（John Doe / Acme / 99.99%）→ 用真实感命名与「有机数据」
  - 不用废话词（Elevate / Seamless / 赋能 / 闭环）
- **布局**：`DESIGN_VARIANCE > 4` 时禁止居中 Hero；用分屏 / 左对齐 / 非对称留白；页面限宽 ~1400px；网格优先于百分比计算。
- **质感**：高密度时不套卡片，用分隔线 / 负空间；玻璃拟态要 1px 内边框 + 内阴影；不用外发光。
- **Bento Grid 范式**：浅底（~#f9fafb）+ 纯白卡片（1px 边）+ 大圆角（~2.5rem）+ 扩散柔影 + 标题置于卡外下方 + 卡内留白 32–40px。
- **正面质感配方（与上方「禁 AI 味」互补）**：玻璃拟态 / 霓虹 / 金属 / 发光边框 / 虹彩 / 新拟态等可直接写成 CSS 的「高级感」配方，见 `references/css-quality-recipes.md` —— 先守负向禁令，再用正向质感把页面做"贵"。

## 第 3 层：场景排版规范

### 3a. HTML 分析报告（详见 `references/html-report-style.md`）

- **交付前必做 JS 自校**：抽内联 `<script>` 跑 `node --check`，有错改到通过再交付——括号失配会让整页图表全空（不是缺一个，是全空）。
- **风格**：浅底深字研报风；首屏结论先行（TL;DR / 关键数字卡）；目标市场惯例配色（如 A 股语境红涨绿跌，其他市场按当地惯例）。
- **图表分工**：有数值轴的数据用 ECharts；关系拓扑（产业链 / 股权结构）用 SVG 或 HTML+CSS；查阅 / 多维对照用表格。
- **质量细则**：图/表可切换；多取一个完整周期消除空值；双轴注意量级差；空值不入图。
- 附 ECharts 柱 / 折（含双轴）/ 饼 / 雷达 / K 线骨架，套用只改 `data` 即可，括号失配率≈0。

### 3b. 幻灯片（详见 `references/slide-guidelines.md`）

- **字号契约**：正文 ≥28px、标题 ≥56px、章节 ≥40px、标签 ≥22px（绝不更低）、关键数字 56–96px（单 KPI 可 120+）。
- **一页一意**；放不下就拆 / 删，绝不缩字号；最多 2 种字体；高对比；用 CRAP 原则。
- **20 个布局契约 L01–L20**（封面 / 章节 / 对比 / KPI / 流程 / 矩阵 / 数据 / 收尾…），按意图选用。
- 16:9 / 1920×1080，内容离边 ≥100px。

### 3c. 通用 UI / 网页 / 落地页 / 表格（详见 `references/ui-layout-principles.md`）

- **16 条通用产品设计定律**：目的优先 / 主导区域 / 可理解性 / 渐进披露 / 识别优于回忆 / 状态可见 / 操作层级 / 结构一致 / 密度可控 / 空间逻辑 / 反馈 / 响应式 / 实体完整 / 约束优于装饰 / 可扩展 / 适配推断。
- **落地页**：内容先于视觉；Hero 单屏单点（标题卖"成为谁"而非"是什么"）；章节池按需选取不堆全；章节间视觉节奏交替，避免 AI 味模板感。
- **表格**：表头 + 数据行结构；宽表在移动端转卡片而非横向滚动；占位用可信有机数据。
- **移动 / 响应式**：所有内容进单一容器、统一定内边距、`gap` 纵向间距、单滚动容器、舒适触控目标、底部胶囊导航、加载/空/错/成四态齐备。

## 使用工作流

1. 判断交付物类型（报告 / 幻灯片 / 文档 / 图）→ 选对应规范与参考文件。
2. 按规范产出文件（HTML 内联资源、SVG/CSS、MD……）。
3. 交付前自检（JS 语法 `node --check` / 可访问性 / 主题对比 / 空值）。
4. 把文件写到工作区并给路径；对话只给一句结论。
